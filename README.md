# AI File Organizer

AI File Organizer 是一款 Local First 桌面文件整理应用。当前版本可以安全扫描用户明确选择的目录，在系统应用数据目录中建立 SQLite 元数据索引，并提供文件与目录浏览、分页搜索、排序、筛选、磁盘变化监听以及经过预览确认的普通文件移动和重命名。阶段五已接入本地 AI 内容分析初版，最终控制权仍保留给用户。

仓库已经完成以下基础文件管理能力：

- 使用原生目录选择器授权扫描根目录；
- 只读递归扫描文件、目录和链接元数据，并汇总忽略项与单项错误；
- 将可重建索引保存在系统应用数据目录中的 SQLite 数据库；
- 浏览目录与文件，按名称、路径、类型、大小和修改时间搜索、排序、筛选及分页；
- 监听当前授权目录的新增、修改、重命名和删除事件，并同步索引与界面；
- 重启后恢复最近使用的持久化索引。
- 普通文件移动和重命名经过 Rust 全量校验、From/To 预览、明确确认和执行前复核；目标冲突、目录对象、未授权路径、跨卷移动和覆盖均被拒绝。
- 实际执行结果持久保存到应用数据目录中的 SQLite，支持根据当前磁盘状态逐项撤销。

阶段五已加入本地 Ollama/Qwen2.5 内容分析初版：仅在用户明确选择文件、配置并启用至少一个分类后，读取 TXT、MD、文本型 PDF、DOCX 以及常见编程语言和配置文件正文；生成摘要、关键词、重命名和已有分类建议。当前版本不会删除、覆盖、执行任意目录操作或向远程 Provider 发送正文；仅当用户接受 AI 分类建议并确认预览后，Rust 执行层才能安全创建或复用授权根目录下的一层分类目录。

## 开发环境

### 前置条件

- Node.js 24
- pnpm 11
- Rust stable 工具链及 `rustfmt`
- 当前平台所需的 [Tauri 系统依赖](https://v2.tauri.app/start/prerequisites/)

Windows 桌面构建需要 Microsoft C++ Build Tools 和 WebView2。macOS 与 Linux 需要安装 Tauri 文档列出的对应原生依赖。

### 安装

```powershell
pnpm install --frozen-lockfile
```

pnpm 只获准运行 esbuild 必需的安装脚本；该白名单记录在 `pnpm-workspace.yaml`。

### 开发与检查

```powershell
# 浏览器开发服务器
pnpm dev

# Tauri 桌面开发应用
pnpm tauri dev

# 前端类型检查、测试和生产构建
pnpm check
pnpm check:all

# 分项前端检查
pnpm typecheck
pnpm test
pnpm build

# Rust 检查
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml

# 调试安装包
pnpm tauri build --debug
```

### 给其他人安装

普通用户不需要安装 Node.js、pnpm、Rust 或源代码。维护者发布版本后，请让用户从 GitHub Releases 下载 Windows x64 的 `*-setup.exe`，双击安装即可。安装包会包含应用本身；如果电脑缺少 WebView2，安装器会尝试联网安装运行时。

文件扫描、浏览、搜索、手动移动、重命名和撤销不依赖 AI。要使用内容分析和分类建议，用户还需要在应用设置中配置本地 Ollama 与模型，或配置 OpenAI 兼容 API。具体发布和验收步骤见[Windows 分发与发布验收](./docs/DISTRIBUTION_WINDOWS.md)。

向 GitHub 推送形如 `v0.1.0` 的版本标签后，GitHub Actions 会在 Windows runner 上运行检查、构建 NSIS/MSI 安装包并创建 Draft Release。发布前仍必须在干净 Windows 电脑上完成桌面人工验收；未签名安装包可能触发 Windows SmartScreen 的“未知发布者”提示。

当前应用只注册扫描、索引状态、索引重建、最近索引恢复、搜索、操作和阶段五 AI 分析等窄化 Tauri Command，并只授予原生目录选择所需的 Dialog 权限。前端不能直接访问文件系统、SQLite、Ollama 或 Shell；只有用户选择目录后才会启动只读扫描和授权范围内的变化监听，且文件写入必须经由一次性操作计划。

## 核心原则

- **Local First**：文件保留在本地，提取出的原始正文只在分析任务内存中短暂存在；SQLite 保存可重建索引、AI 分析结果、应用元数据和操作历史。
- **AI 只提供建议**：AI 不能直接移动、重命名、删除或撤销文件操作。
- **先预览再确认**：移动和重命名必须经过 Rust 校验，并向用户展示 From/To 预览。
- **不静默覆盖**：目标路径存在任何文件或目录时拒绝执行。
- **操作可追踪**：实际操作写入持久历史，并在当前磁盘状态允许时支持撤销。
- **最小权限**：前端不直接访问文件系统、SQLite 或 Shell，后端不暴露通用文件操作入口。

## v0.1.0 能力与计划

阶段一至四已完成：

- 扫描用户明确选择的本地目录，并建立 SQLite 文件元数据索引；
- 浏览、搜索、排序和筛选索引中的文件与目录；
- 监听授权目录变化，仅更新索引，不自动整理文件。
- 移动和重命名普通文件，批量移动支持全量预检、逐项结果和失败后停止后续项目。
- 长期保存操作历史，并在源路径未被占用、目标文件身份匹配时支持撤销。

阶段五已实现的初版能力：
- 对用户明确选择的文本型 PDF、TXT、MD、DOCX、常见编程语言和配置文件在本地提取正文，根据内容与元数据生成摘要、关键词、智能重命名和分类建议。
- 长文档采用“分段摘要后汇总”；Ollama 以受限 JSON Schema 输出，由 Rust 再次校验。
- AI 只能返回用户配置的已有分类 ID；Rust 将其映射为授权根目录下的单层分类目录。该目录可在预览时不存在，只有用户确认后才由执行层安全创建或复用；无法匹配时只建议重命名。

阶段五仍待发布验收：
- 使用 80–120 份真实非敏感文档完成黄金集评测并达到发布门槛；未达标时先优化程序约束、提示词和少样本示例。
- 完成真实桌面端人工流程验收；当前自动化测试不等同于已验证 Ollama、文件选择、预览确认和撤销的实际桌面体验。
- 远程 Provider、OCR、XLSX、PPTX、旧版 `.doc`、多模态分析及 QLoRA 训练均不属于首版范围；QLoRA 是后续研究，不是 v0.1.0 发布门槛。

第一版不支持删除、覆盖、用户或模型发起的任意目录操作、跨卷移动、旧版 `.doc`、XLSX、PPTX、OCR 或多模态内容理解。唯一目录创建例外是：确认后的 AI 分类操作可创建授权根目录下、由已配置分类 ID 派生的一层目录。扫描版或图片型 PDF 不会在第一版进行内容分析。代码文件按受限纯文本读取，不执行代码，也不进行语法树或依赖分析。

## AI 内容与隐私边界

- 目录扫描只建立文件元数据索引，不会自动读取或发送正文；内容分析必须由用户明确选择文件后发起。
- 提取出的原始正文不写入 SQLite、操作历史或日志。SQLite 只保存摘要、关键词、建议、置信度、理由、Provider/模型标识、分析时间、文件身份、内容指纹和采用状态。
- 内容提取时同步计算只用于 AI 分析结果的内容指纹；文件在分析后发生变化时，既有结果标记为过期。AI 派生的草案和计划携带该指纹并在执行前复核；手动普通操作仍不强制计算内容哈希。
- AI 不接收文件执行权限，不返回可直接执行的绝对路径，也不能请求任意目录创建或绕过用户确认；受控分类目录只由 Rust 在确认后的执行阶段创建。
