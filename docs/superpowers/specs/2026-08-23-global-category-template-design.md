# 全局分类模板与分析前模板选择设计

## 1. 状态与目标

本文是模板体系的目标设计，更新了原先“把模板应用到当前目录后再分析”的方案。

当前已实现：

- 模板查询、保存、删除；
- 将模板复制为当前授权根目录的本地分类配置；
- 根目录与已应用模板 ID、版本的绑定；
- 分析结果记录可空的模板 ID、版本；
- 本地分类的安全删除保护。

目标变更：

- 支持显式设置一个全局默认模板；
- 支持新建、查看、修改和删除已保存模板；
- 非全局模板支持重命名；
- 设置页删除“应用模板”按钮；
- 用户在文件浏览页、开始 AI 分析前选择全局模板、其他模板或当前目录自定义分类；
- 选择模板不再把模板复制到当前目录，也不产生文件系统变化。

本文件不声明这些目标功能已经完成。实现仍需单独修改 React、Tauri Command、Rust 服务、数据库迁移和测试。

## 2. 核心语义

### 2.1 模板

模板是一组可复用的分类定义，包含：

- 稳定的模板 ID；
- 用户可见名称；
- 模板版本；
- 分类列表：稳定分类 ID、名称、描述、默认启用状态；
- 创建时间和更新时间。

模板不得保存绝对路径、任意相对路径或目录创建指令。分类 ID 才是模型输出和安全目录映射的稳定语义标识。

### 2.2 全局模板

“全局”表示文件浏览页开始分析时的默认分类模板，不表示模板已经应用到每个目录。

- 系统允许零个或一个全局模板。
- 设置全局模板后，同一时刻必须恰好有一个全局引用。
- 全局模板可修改分类内容，但不能重命名或删除。
- 将另一模板设为全局时，旧全局模板自动变为普通模板。
- 设为全局不复制分类、不创建目录、不移动文件，也不改变历史分析结果。

允许零个全局模板是为了兼容首次启动和旧数据库迁移。没有全局模板时，文件页必须要求用户显式选择分类来源，不能静默猜测。

### 2.3 当前目录自定义分类

根目录本地分类配置继续保留，作为分析时可选的另一种来源。它与模板库相互独立：

- 修改本地分类不修改模板；
- 修改模板不回写本地分类；
- 删除本地分类配置不删除物理目录或文件；
- 本地分类不能设为全局模板。

## 3. 用户流程

### 3.1 模板管理

设置页提供模板库与模板编辑器：

- 新建模板；
- 查看和修改模板分类；
- 重命名非全局模板；
- 将非全局模板设为全局；
- 删除非全局模板。

不再提供“应用模板”按钮。保存模板只保存模板本身。

### 3.2 分析前选择

文件浏览页在用户选择文件后显示“分类方案”：

1. 默认选中全局模板；
2. 用户可改选其他已保存模板；
3. 用户可改选当前目录自定义分类；
4. 点击分析时才把分类来源提交给 Rust；
5. Rust 读取并冻结真实模板版本与启用分类后启动任务。

模板选择只影响本次分析。它不能修改目录配置，也不能跳过建议审查、操作预览和最终确认。

## 4. 版本与并发规则

- 新建模板从版本 `1` 开始。
- 分类内容新增、修改、删除或启用状态变化时，版本递增。
- 单纯重命名不改变分类语义，因此只更新名称与 `updated_at`，不递增版本。
- 设为全局只改变全局引用，不递增模板版本。
- 开始分析时，前端提交模板 ID 和它最后看到的版本；Rust 必须重新读取并比较。
- 版本不一致时拒绝启动并要求刷新，防止用户在不知情的情况下使用已变化模板。
- 分析启动后冻结模板 ID、版本和分类快照；后续模板修改不改变已运行批次和历史结果。

## 5. 数据库设计

### 5.1 保留现有结构

保留：

- `ai_category_templates`
- `ai_category_template_items`
- `ai_root_category_templates`
- `ai_analysis_results.template_id`
- `ai_analysis_results.template_version`

`ai_root_category_templates` 暂时保留用于兼容既有根目录配置和历史来源追踪，不再作为新界面开始模板分析的前置条件。迁移不得破坏已有绑定。

### 5.2 新增全局引用

新增单行设置表，而不是在每个模板行上保存可产生多个 `true` 的布尔值：

```sql
CREATE TABLE ai_template_settings (
    singleton_id INTEGER PRIMARY KEY CHECK (singleton_id = 1),
    global_template_id TEXT,
    updated_at TEXT NOT NULL,
    FOREIGN KEY (global_template_id)
        REFERENCES ai_category_templates(template_id)
        ON DELETE RESTRICT
);
```

这一结构从数据库层表达“最多一个全局模板”。旧数据库升级时不自动猜测全局模板；初始化一行空引用，用户首次设置后再填入。这样不会因排序或更新时间隐式改变用户默认设置。

### 5.3 删除与历史

- 删除全局模板必须被数据库引用和服务规则共同拒绝。
- 删除非全局模板不得删除 `ai_analysis_results` 历史记录。
- 历史结果中的模板 ID 与版本是来源快照，不要求模板仍然存在。
- 旧的根目录模板绑定若使用 `ON DELETE RESTRICT`，删除前必须给出明确占用提示，或通过独立兼容迁移将其转换为不会阻止安全删除的历史快照；不得直接级联删除本地分类。

## 6. 类型与接口目标

### 6.1 公共类型

模板列表返回值增加：

```ts
type AiCategoryTemplate = {
  id: string;
  name: string;
  version: number;
  is_global: boolean;
  categories: TemplateCategory[];
};
```

分析请求增加显式分类来源：

```ts
type AnalysisCategorySource =
  | { kind: "template"; template_id: string; expected_version: number }
  | { kind: "root_custom" };
```

### 6.2 Tauri Command

保留并调整：

- `get_ai_category_templates`：返回 `is_global`。
- `save_ai_category_template`：新建或修改分类内容；全局模板允许修改内容，但名称变更必须拒绝。
- `delete_ai_category_template`：仅允许删除非全局模板，并处理旧绑定占用。
- `start_analysis_batch`：新增 `category_source`，由 Rust 解析模板或当前目录分类。

新增：

- `rename_ai_category_template(template_id, name)`：仅非全局模板；不递增语义版本。
- `set_global_ai_category_template(template_id)`：事务性替换唯一全局引用。

逐步停用：

- `apply_ai_category_template`：新界面不再调用。第一阶段保留为兼容接口并标记弃用；确认无旧调用、迁移完成后再单独删除，避免本次设计变更破坏已有数据流程。

前端不能通过隐藏按钮代替后端权限校验。重命名全局模板、删除全局模板、选择不存在模板和提交陈旧版本都必须由 Rust 拒绝。

## 7. Rust 分析解析规则

`start_analysis_batch` 接收到分类来源后：

1. 重新确认 `root_path` 是当前授权根目录。
2. 校验 1–100 个文件均在授权范围内且为支持的普通文件。
3. 若来源为模板，读取模板并比较 `expected_version`。
4. 若来源为当前目录分类，读取该根目录的本地分类。
5. 要求至少一个启用分类。
6. 验证分类 ID、名称与单层安全目录映射；拒绝绝对路径、分隔符、重复 ID 和大小写冲突。
7. 将启用分类与来源信息冻结到任务输入。
8. 分析结果写入模板 ID、模板版本；当前目录分类来源写空值。

不得信任前端传回的完整模板分类数组。前端只传来源标识，真实分类必须由 Rust 从 SQLite 读取。

## 8. 文件系统安全边界

模板管理和模板选择都属于配置/分析行为：

- 不创建目录；
- 不移动或重命名文件；
- 不允许模型输出路径；
- 不向 AI 暴露执行接口或 `planId` 权限。

AI 只输出有效分类 ID 和受约束的建议文件名。用户接受建议后仍必须经过：

```text
分析结果
  → Rust 生成操作草案
  → 整批安全校验
  → From/To 预览
  → 用户确认 planId
  → 执行前文件身份与目标复核
  → 执行、历史与撤销资格
```

只有已确认的 `AiOrganize` 计划，才能在授权根目录内创建或复用由有效分类 ID 派生的一层分类目录。

## 9. 本地分类安全删除

现有保护继续有效。删除当前根目录分类前，后端检查：

- 是否存在待确认 AI 结果引用该分类；
- 是否存在待确认操作草案指向该分类目录；
- 分类映射是否仍位于当前授权根目录内。

删除只移除 SQLite 分类配置，不删除目录，不移动或删除目录中的文件。模板内删除分类也只影响模板的新版本，不修改使用旧版本产生的历史结果。

## 10. 迁移顺序

1. 新增 `ai_template_settings` 与仓储测试。
2. 扩展 Rust 模型、模板查询、重命名和设为全局接口。
3. 扩展分析请求并在 Rust 中解析、冻结分类来源。
4. 更新 TypeScript 类型和调用封装。
5. 重构设置页为模板库/编辑器，移除“应用模板”。
6. 在文件浏览页加入分类方案选择并传给分析请求。
7. 保留旧应用接口进行一轮兼容验证，确认无调用后另行决定删除。

不得在迁移过程中删除现有表、根目录分类、历史结果或用户模板。

## 11. 验证要求

### 11.1 仓储与接口

- 全局引用最多一个，事务切换成功。
- 全局模板不能重命名或删除，直接调用后端同样失败。
- 非全局模板可重命名，模板版本不变。
- 分类内容修改使版本递增。
- 删除非全局模板不删除历史结果和文件系统内容。
- 旧根目录绑定在迁移后仍可读取。

### 11.2 分析

- 全局模板在文件页默认选中。
- 用户可选择任意其他模板或当前目录自定义分类。
- 模板选择不会写入根目录分类表，不会创建目录。
- 不存在模板、陈旧版本、空分类和非法分类均阻止分析。
- 分析批次使用冻结版本，模板后续修改不改变批次。
- 结果正确记录模板 ID 与版本。

### 11.3 安全链与界面

- 接受建议仍只生成预览计划。
- 取消计划不产生磁盘变化。
- 只有确认有效 `planId` 后才允许执行和安全创建分类目录。
- 设置页没有“应用模板”按钮。
- 全局模板不显示重命名和删除；非全局模板显示完整管理动作。
- 文件页的模板选择、设置页的全局状态和分析结果来源保持一致。

## 12. 非目标

- 不训练或微调模型。
- 不改变 Provider 选择与远程数据同意策略。
- 不允许模板保存任意路径或多层目录。
- 不自动把模板同步到所有授权目录。
- 不绕过阶段四预览、确认、执行复核、历史和撤销机制。
