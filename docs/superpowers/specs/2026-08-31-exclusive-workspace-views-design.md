# 独占式工作区视图设计

## 1. 背景与问题

当前应用已经有左侧五个导航入口，但 `FilesFeature` 同时渲染文件浏览、AI 建议、操作预览、历史与模板设置。`activeView` 只影响少数组件的显隐，未形成真正的页面边界，因此用户点击导航后仍可能在同一页面看到多个工作区。

本次设计采用方案 A：保留现有应用壳层和业务控制器，将主内容改为“当前导航只渲染一个独占视图”。本次不引入 React Router，不改变 Rust 安全链路和现有 Tauri API。

## 2. 目标与非目标

### 目标

- 五个一级导航对应五个互斥的主视图。
- 保留当前扫描、索引、AI 分析、模板管理、操作预览、执行、历史和撤销逻辑。
- 在视图切换时保留控制器中的选择、分析结果、模板草稿和 `planId` 状态。
- 让关键流程按阶段自然跳转：文件选择 → AI 审查 → 操作预览 → 执行结果/历史。
- 无数据时显示当前视图的明确空状态，不渲染其他工作区内容。
- 不绕过 Rust 的预览、确认、执行时复核、历史和撤销安全边界。

### 非目标

- 不引入 URL 路由、深链接或浏览器历史。
- 不重写 Rust 命令、数据库模型或操作安全策略。
- 不在本次工作中新增文件整理能力。
- 不复制 HTML 原型中的静态演示数据。

## 3. 视图边界

| 视图 | 唯一职责 | 允许显示的内容 |
| --- | --- | --- |
| `files` | 浏览和选择文件 | 目录状态、搜索筛选、文件表格、选择栏、手动批量操作 |
| `ai` | 审查 AI 建议 | 模型状态、分类来源、分析进度、建议卡片、接受/修改/拒绝 |
| `preview` | 确认即将执行的变更 | From → To 列表、冲突/失效状态、取消计划、确认并执行 |
| `history` | 查看已完成操作并撤销 | 时间、操作摘要、执行状态、撤销动作 |
| `settings` | 管理模板和分类 | 全局模板、已保存模板、模板编辑器、当前目录自定义分类 |

文件浏览页可以提供进入 AI 分析的准备操作，但不显示 AI 建议卡片。AI 页面不显示完整文件表格；它只使用已选择文件或已生成的分析批次。

## 4. 组件与状态架构

保留 `FilesFeature` 作为状态和 API 控制器，新增一个纯渲染分发层（可命名为 `WorkspaceViewContent` 或等价名称）。分发层只根据 `activeView` 选择一个页面组件，不复制任何业务状态机。

```text
App
└─ WorkspaceShell
   ├─ Sidebar
   ├─ TopBar
   └─ FilesFeature（业务控制器）
      └─ WorkspaceViewContent（互斥分发）
         ├─ FileBrowserPage
         ├─ AiReviewPage
         ├─ OperationPreviewPage
         ├─ OperationHistoryPage
         └─ TemplateSettingsPage
```

### 状态归属

- `App`：当前 `activeView` 和导航回调。
- `FilesFeature`：授权目录、索引状态、文件选择、AI 批次、模板、预览计划、执行结果、历史和错误状态。
- 页面组件：只接收数据和回调；不直接调用 Tauri API，不创建第二套状态机。
- `WorkspaceShell`：只负责壳层、导航和顶栏，不负责业务条件判断。

### 导航回调

为 `FilesFeature` 增加窄接口 `onNavigate(view)`，由流程事件触发必要的页面切换：

- 生成有效操作预览后切换到 `preview`。
- 分析批次完成且存在结果后切换到 `ai`。
- 执行完成后保留结果提示，并允许进入 `history` 或返回 `files`。
- 取消预览后返回 `ai`，不清空仍可继续审查的分析结果。
- “管理分类”进入 `settings`，保存/取消后返回来源视图。

用户点击侧栏时只改变 `activeView`，不得静默取消后台分析或操作计划。若离开设置页存在未保存模板编辑，应沿用现有保存/放弃/留在当前页保护。

## 5. 页面数据与空状态

每个视图都必须能独立处理“无数据、加载中、成功、失败”四类状态：

- `files` 无授权目录：显示选择目录入口，不显示空表格和其他页面。
- `ai` 无选择文件：提示先到文件浏览页选择文件，并提供返回入口。
- `preview` 无有效 `planId`：显示没有待确认计划，并提供返回 AI 审查入口。
- `history` 无记录：显示尚无执行记录，不显示文件浏览器。
- `settings` 无模板：显示新建模板入口，同时保留当前目录分类设置（若存在）。

系统错误可显示在当前视图顶部；错误消息不得导致其他视图同时展开。

## 6. 安全与行为约束

- 页面切换不等于取消分析、预览或执行任务。
- “确认并执行”只提交现有 `planId`，不从页面重新拼装源路径和目标路径。
- “取消计划”只取消计划，不修改磁盘，也不删除分析结果。
- 接受 AI 建议仍然只进入操作预览，不直接修改文件。
- 所有模板选择、分类编辑和文件操作继续经过现有后端校验。
- 视图拆分不得把真实运行状态替换成 HTML 原型中的固定示例。

## 7. 实施范围

### 需要修改

- `src/features/files/FilesFeature.tsx`：从“全部内容页面”改为业务控制器 + 独占视图分发。
- `src/app/App.tsx`：向 `FilesFeature` 传递导航回调（如采用当前状态归属）。
- `src/features/ai/AiPanel.tsx`：保留控制逻辑，拆出或复用 AI 准备区与建议审查区。
- `src/features/operations/*View.tsx`：补充无数据状态和独占布局所需的入口。
- 必要时新增页面容器组件，保持现有 API 组件可独立测试。

### 不需要修改

- Rust 命令和安全策略。
- 文件扫描和搜索 API。
- 模板、操作预览和历史 API 的接口语义。

## 8. 验收标准

1. 点击五个导航项时，主区域只出现对应视图的标题和内容。
2. `files` 页面不出现 AI 建议卡片、操作历史或模板编辑器。
3. `ai` 页面不出现完整文件表格、操作历史或模板库。
4. `preview` 页面只出现当前计划及“取消计划/确认并执行”操作。
5. `history` 页面只出现历史记录和撤销状态。
6. `settings` 页面只出现模板和分类设置，不出现“应用模板”按钮。
7. 选择文件、分析、接受建议、预览、执行、历史和撤销的现有测试继续通过。
8. 视图切换不会绕过或削弱 Rust 的安全确认链路。
9. 950px 和 650px 断点下独占视图没有横向溢出、内容重叠或不可操作按钮。

## 9. 验证策略

- 为 `FilesFeature` 或分发层增加视图互斥测试：每个 `activeView` 只渲染一个页面标识。
- 保留并扩展 AI、操作预览、历史和模板现有测试，覆盖空状态和导航回调。
- 运行 `pnpm check`，确认类型检查、Vitest 和生产构建通过。
- 使用实际运行时数据检查五个视图，不以静态 HTML 示例代替行为验收。
