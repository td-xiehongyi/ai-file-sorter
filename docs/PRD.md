## 文档目的

本文档定义 AI File Sorter 第一版要解决的问题、目标用户、产品范围、核心体验和产品验收标准。系统分层见[系统架构](./ARCHITECTURE.md)，规范性安全规则见[安全模型](./SAFETY_MODEL.md)，实施顺序见[开发路线图](./ROADMAP.md)。

## 产品背景

下载目录、工作资料和个人文档会随着时间积累。传统文件管理器能够移动和重命名文件，但用户仍需逐项判断文件用途、设计名称并选择归档位置；能够自动整理的工具又容易隐藏决策过程，带来误移动、覆盖、删除或隐私外发风险。

AI File Sorter 希望在效率和控制之间建立清晰边界：应用负责建立本地索引、呈现文件状态和执行受控操作，AI 只负责生成可审查的建议，用户始终决定是否执行。

## 目标用户

- 希望整理下载目录、账单、学习资料或工作文档，但不愿把文件控制权交给自动化工具的个人用户。
- 需要快速搜索和分类大量本地文件，同时关心路径、文件名或内容隐私的用户。
- 希望在执行前看清每一项变化，并在条件允许时能够撤销的谨慎型用户。

## 产品目标

- 让用户能够在一个桌面应用中扫描、浏览、搜索和筛选已授权目录中的文件。
- 让移动与重命名操作在执行前可理解、可校验、可确认，执行后可追踪。
- 让 AI 建议复用与手动操作相同的安全管线，不能绕过程序校验和用户确认。
- 让用户能够基于文档正文获得摘要、关键词、智能重命名和分类建议，而不必把原始正文持久保存在应用中。
- 在不依赖 AI 或远程服务的情况下，基础文件管理功能仍然可用。
- 默认将文件和应用数据保留在本机，并让远程数据发送行为对用户透明。

## 产品原则

- **用户授权优先**：只扫描用户明确选择的真实目录，不通过链接扩展授权范围。
- **文件系统为准**：SQLite 是索引和历史层，不能替代执行前的磁盘状态复核。
- **建议与执行隔离**：用户输入和 AI 输出都先成为未信任的操作草案。
- **变化必须可见**：移动与重命名至少展示来源路径、目标路径、操作类型和校验结果。
- **失败必须真实**：批量操作逐项记录成功、失败和未执行状态，不声称文件系统操作具有数据库式原子性。
- **隐私选择明确**：内容分析只处理用户明确选择的文件；使用远程 Provider 前按批展示拟发送的数据范围、预计文本量和可获得的调用次数或费用估算，并取得用户同意。

## v0.1.0 功能范围

### 目录扫描与索引

- 用户通过目录选择界面授权扫描根目录。
- 应用递归读取文件名、路径、扩展名、大小、修改时间等基础元数据。
- 符号链接、Windows Junction 和其他目录重解析点只记录条目，默认不遍历目标。
- SQLite 位于系统应用数据目录；扫描目录中不写入数据库或旁车文件。
- 支持全量扫描、增量更新和不清除操作历史的索引重建。

### 浏览、搜索与变化同步

- 展示已索引的目录和文件列表。
- 支持按名称、路径、类型、大小和修改时间搜索、排序或筛选。
- 大量结果通过分页或虚拟列表展示，避免阻塞界面。
- 文件监听只同步索引状态，不触发自动整理。

### 安全文件操作

- 第一版只处理普通文件的同卷移动与重命名。手动移动的目标目录必须已经存在；AI 分类操作是受控例外，且只能在用户确认后创建授权根目录下由已配置分类 ID 派生的一层目录。
- 用户或 AI 提交的操作草案由 Rust 后端全量校验。
- 校验成功后生成只在内存中存在、有效期为 10 分钟的一次性 `planId`。
- 用户查看 From/To 预览并明确确认 `planId` 后，后端再次复核文件身份和目标冲突再执行。
- 目标存在、源文件变化、计划失效或权限不足时拒绝危险操作，并返回可理解的原因。

### 历史与撤销

- 每次实际文件操作持久记录逐项请求和真实结果。
- 操作历史默认长期保留，不随文件索引重建而清除。
- 撤销资格根据当前磁盘状态动态计算；恢复位置被占用、文件缺失或身份不匹配时拒绝撤销。
- 批量执行发生运行时失败后停止后续项目，已成功项目可以通过正常撤销流程逐项恢复。

### AI 整理建议

- 目录扫描不读取正文。只有用户主动发起内容分析时，应用才处理其明确选择的文件。
- 第一版支持可直接提取文字的文本型 PDF、TXT、MD、DOCX 和常见代码/配置文本文件；不支持旧版 `.doc`、XLSX、PPTX、OCR 或多模态理解。
- Rust 在本地识别真实格式并提取正文；短文档直接分析，超过单次模型输入预算的长文档分段摘要后再汇总。
- 提取出的原始正文只在当前分析任务内存中短暂存在，不写入 SQLite、操作历史或日志。
- AI 必须输出严格的结构化结果：`summary` 为非空字符串，`keywords` 为非空字符串数组，`suggested_filename` 为不含路径且扩展名与源文件一致的合法文件名，`category_id` 为已有分类 ID 或 `null`，`confidence` 为 `[0, 1]` 范围内的数字，`reason` 为非空字符串。缺少字段、出现额外字段、类型错误、空必填值或越界值时整项拒绝。
- 用户预先配置分类 ID 与安全目录标签的映射。Rust 将标签派生为授权根目录下的一层目标目录；该目录可在分析和预览时不存在，但只可在确认后的 AI 分类执行中创建或复用。AI 只能选择已有分类 ID，不能返回绝对目标路径或请求任意目录创建；无法匹配时只生成重命名建议。
- 默认优先本地模型或用户主动配置的 Provider。
- 使用远程 Provider 时，每批发送前展示确切文件及版本、Provider/模型、拟发送字段、预计字符或 token 数、分段与调用次数、最大重试预算，以及费用范围；Provider 无法估算费用时必须明确显示“无法估算”。确认后生成一次性批次同意凭据，任一绑定项变化、超出预算、取消、消费或过期都必须重新确认，未持有有效凭据时不得发送正文。
- SQLite 可以保存摘要、关键词、建议、置信度、理由、Provider/模型标识、分析时间、对应文件身份、内容指纹和采用状态，但不能保存提取出的原始正文。
- 内容提取时在读取字节的同时计算只用于 AI 分析的内容指纹，并在提取结束及持久化前复核文件元数据与平台身份；分析期间发生变化时丢弃结果。持久结果绑定内容指纹，转换为操作草案前重新核对；AI 派生的草案和计划继续携带该指纹，Rust 在执行前再次核对。不一致时结果或计划失效。该规则不改变阶段四“手动普通文件操作第一版不计算内容哈希”的范围。
- 用户可以逐项接受、修改或拒绝建议；接受后的建议仍须经过校验、预览和确认。
- 扫描 PDF、加密或损坏文档、空文本、伪装扩展名、解码失败、超出资源限制、Provider 不可用、输出非法或用户拒绝建议时，展示明确状态且不生成可执行建议，也不影响扫描、浏览、搜索和手动整理。

## 核心用户流程

```text
选择本地目录
  → 只读扫描并建立索引
  → 浏览、搜索或筛选文件
  → 用户手动创建草案，或明确选择文件请求内容分析
  → 本地识别格式并提取临时正文
  → 远程 Provider 按批确认发送范围，或直接调用本地 Provider
  → AI 返回结构化摘要、关键词、重命名与已有分类建议
  → 用户选择要采用的建议
  → Rust 全量校验并生成预览计划
  → 用户核对 From/To 并确认 planId
  → Rust 执行前复核并逐项执行
  → 展示真实结果并保存历史
  → 根据当前磁盘状态提供撤销资格
```

## 第一版非目标

- 删除文件或目录，以及任何删除 Command、执行器或界面。
- 创建、移动或重命名任意目录；唯一例外是确认后的 AI 分类操作创建由已配置分类 ID 派生、位于授权根目录下的一层目录。
- 覆盖、替换、自动合并、自动编号或静默改名。
- 跨磁盘或跨文件系统移动，以及用复制后删除模拟跨卷移动。
- AI 自动确认或直接执行文件操作。
- AI 返回或执行绝对目标路径、创建目录，或选择用户未配置的分类目标。
- 在目录扫描、监听或无人值守任务中自动读取正文、调用 AI 或整理文件。
- 旧版 `.doc`、XLSX、PPTX、扫描版或图片型 PDF 的 OCR，以及图表、公式和页面图像的多模态理解。
- 未经本批用户同意向远程服务发送正文、敏感路径或文件元数据。
- 将提取出的原始正文写入 SQLite、操作历史、应用日志或扫描目录中的旁车文件。
- 由前端指定 SQLite 位置、直接执行 SQL、Shell 命令或任意文件系统操作。

## 产品验收标准

- 用户能够选择目录并看到扫描进度、结果摘要以及可搜索的文件列表。
- 扫描和监听不会通过符号链接或 Junction 越出授权边界，也不会修改被扫描目录。
- 没有有效预览和明确确认时，任何移动或重命名都不能执行。
- 目标冲突、跨卷目标、目录对象和执行前源文件变化均被拒绝，且不会覆盖现有内容。
- 所有实际操作结果与磁盘真实状态一致，历史在索引重建后仍然存在。
- 撤销前重新判断资格，冲突情况下拒绝覆盖。
- AI 无法直接调用文件执行能力；AI 不可用时基础文件管理仍正常工作。
- 文本型 PDF、TXT、MD、DOCX 和常见代码/配置文本文件能生成内容摘要、关键词及重命名建议；长文档能够分段摘要后汇总。
- 有效的已有分类 ID 能由 Rust 映射为授权根目录下的一层目录；用户接受后，建议完整经过草案、校验、From/To 预览、确认和执行链，目录只在确认后的执行阶段创建或复用。
- 扫描 PDF、加密或损坏文档、空文本、伪装扩展名、不支持格式、解码失败和资源超限只产生明确错误，不调用 Provider 或生成可执行建议。
- 严格结果校验拒绝缺少字段、额外字段、类型错误、空必填值、非法文件名、未知分类 ID 和越界置信度。
- 未经本批明确同意，不向远程 Provider 发送正文或其他已展示的数据；原始正文不进入 SQLite、操作历史或日志。
- 未知分类 ID、绝对路径和目录创建建议被拒绝；无法匹配现有分类时只允许生成重命名建议。
- 同大小或相同修改时间的内容替换、分析期间变化、应用重启后加载持久结果，以及 AI 草案生成后至执行前的变化，都会被内容指纹复核发现并使旧结果或计划失效。
- Windows、macOS 和 Linux 的核心扫描、搜索、预览、执行和撤销场景均通过验证。

## 交付方式

产品按[开发路线图](./ROADMAP.md)中的六个阶段建设：先建立可运行工程和不依赖 AI 的文件管理基础，再加入安全操作管线与 AI 建议，最后完成跨平台、安全审计和发布验证。每个阶段开始前需要进一步确认该阶段的接口、数据结构和验收细节。
