# ai-file-sorter UI 交互规范

## 1. 文档目的与边界

本文定义完整版界面中的用户操作、状态变化、失败处理和安全边界。React 页面按本文交互接入现有真实接口，安全约束仍由 Rust 实现负责最终裁决。

当前程序已经具备扫描索引、AI 建议、操作预览、确认执行、历史与撤销，以及模板的查询、保存、删除和全局模板设置能力。React 界面已将模板使用方式实现为“分析前选择”；本文继续以 Rust 安全模型和真实 API 作为行为规范。

阶段五当前支持本地 Ollama 与 OpenAI 兼容 API 两种 Provider。Anthropic 专用协议和自定义协议在设置页保持禁用，直到对应适配器完成设计与验证。

任何交互都必须服从 [`../SAFETY_MODEL.md`](../SAFETY_MODEL.md)：React 和 AI 不能直接改文件；移动或重命名必须经过 Rust 校验、预览、明确确认、执行时复核、历史记录和撤销资格判断。

## 2. 全局交互原则

- 用户每次只面对一个明确主任务。
- 选择、分析、接受建议和执行是四个不同阶段，不得合并成一次隐式操作。
- 页面切换不等于取消后台任务；真正取消必须使用对应取消动作。
- 未保存编辑离开页面时应提示“保存 / 放弃 / 留在当前页”。
- 危险操作使用二次确认，并明确对象名称与影响范围。
- 所有失败都保留用户尚可继续使用的输入和选择。

## 3. 文件浏览流程

### 3.1 进入页面

1. 应用读取当前授权根目录、索引状态和文件列表。
2. 顶栏显示真实本地 AI 可用状态；模型名称来自运行时配置，不使用原型示例冒充真实值。
3. 没有授权目录时，主区域显示选择目录入口，不显示空的文件表格。

### 3.2 更换目录

1. 用户点击“选择其他目录”。
2. 系统打开原生目录选择器。
3. 用户取消时保持当前目录和页面状态不变。
4. 用户选择后，由 Rust 建立新的授权根目录并加载索引。
5. 未完成的选择和预览计划不得被静默带入新目录；需要取消或判定失效。

### 3.3 选择文件与分类方案

1. 用户勾选一个或多个普通文件。
2. 页面显示选择操作栏。
3. 分类方案默认值按顺序确定：当前全局模板；若尚未设置全局模板，则显示“请选择分类方案”。
4. 下拉框按“全局默认”和“常用模板”分组展示已保存方案，并另外提供“当前目录自定义分类”；全局模板名称可变更，但仍标注“全局默认”。
5. 更换选择只更新本次待分析的分类来源，不写入当前目录分类配置、不创建目录、不移动文件。
6. 用户点击“管理分类”时进入设置页，并定位到当前选择对应的编辑状态。

### 3.4 配置模型 Provider

1. 用户在设置页选择“本地模型”或“API 模型”。
2. 本地模型显示 Ollama 地址和当前模型；API 模型要求填写 OpenAI 兼容 API 地址、模型名称和 API Key。
3. API 地址必须是 HTTPS；API Key 只保存到系统凭据存储，界面不回显完整密钥，返回配置只显示是否已配置。
4. “测试连接”只执行 Provider 健康检查，不发送文件正文；“保存 API 配置”只保存公共 Provider 元数据和系统凭据引用。
5. Provider 不可用时保留表单内容和分类设置，并显示可恢复的错误。

### 3.5 开始分析

开始分析前必须同时满足：

- 已选择 1–100 个受支持的普通文件；
- 已选择的 Provider 和模型可用；
- 已选择有效分类来源；
- 该来源至少包含一个启用分类。

若选择远程 Provider，还必须在本次点击开始分析前确认正文发送范围。确认框显示所选文件正文将发送到的 Provider、模型和 API 地址；用户拒绝时不发起分析请求。

用户点击“分析所选文件”后：

1. 前端提交文件列表、分类来源标识和 Provider ID；远程分析同时提交本次正文发送同意。
2. Rust 重新确认授权根目录、文件范围、分类来源和 Provider 配置。
3. Rust 读取并冻结模板 ID、模板版本和本次启用分类；若选择当前目录分类，则冻结当前分类快照并将模板字段留空。
4. 页面进入进度状态，禁止对同一选择重复发起分析。
5. 用户可取消任务；取消不删除已完成的历史结果，也不修改文件。
6. 分析完成后进入“AI 建议审查”。

若模板在用户点击分析前已被删除或修改，Rust 拒绝使用陈旧版本，前端刷新模板列表并要求用户重新确认选择。

## 4. AI 建议审查流程

### 4.1 建议卡片

每张卡片使用相同顺序显示：原文件、建议文件名与分类、置信度、原因、操作按钮。失败文件在相同位置显示失败原因和“重试”入口，不改变其他卡片结构。

### 4.2 接受建议

1. 用户点击“接受建议”。
2. Rust 使用分析结果中冻结的分类 ID 和文件身份创建操作草案。
3. 草案通过整批校验后生成 `planId`。
4. 只有 `planId` 创建成功，界面才将该建议标记为“已加入预览”。
5. 用户仍需进入操作预览并确认，接受建议本身不会修改磁盘。

### 4.1 批次审查门槛

- 一个分析批次中的每条结果都必须先由用户选择“接受建议”或“拒绝”；单条接受只更新当前卡片状态，不跳转到操作预览。
- 所有结果完成选择后，前端将接受项合并为一个操作草案并只创建一个预览计划；混合接受/拒绝时，仅接受项进入计划。
- Rust 在同一批次确认命令中逐条复核文件指纹、目标路径和计划项目数量/顺序，全部匹配后才把结果标记为 `accepted`。
- 全部拒绝时不创建操作计划，页面保留在审查页并明确提示没有待执行操作；任何复核失败都保持相关结果待审查并取消临时计划。
- 若批次完成但没有任何可审查结果，页面必须显示失败数量和重试提示，不能只留下“completed”进度而让用户误以为结果丢失。

### 4.3 修改建议

1. 用户点击“修改”。
2. 卡片进入内联编辑，允许修改建议文件名和选择本次分析快照中存在的分类。
3. 保存时由 Rust 重新校验文件名、分类 ID、目标边界和冲突。
4. 校验失败时保留编辑内容并显示字段级错误。
5. 校验成功后生成或更新预览草案，不直接执行。

### 4.4 拒绝建议

拒绝只改变建议审查状态，不修改文件。若该结果已生成待确认草案，应先取消相应草案或将其从批次预览中移除。

## 5. 操作预览与执行

### 5.1 预览

- 页面逐项显示完整的 From → To 关系。
- 若目标分类目录尚不存在，只显示“将创建目录”，预览阶段不得创建目录。
- 任一项目存在冲突、越界、链接风险、文件身份变化或跨卷问题时，整批计划不可确认。
- 用户可返回审查页修改建议；原 `planId` 应取消或失效，不能复用陈旧计划。

### 5.2 取消计划

点击“取消计划”后取消当前 `planId`，返回上一工作页面。取消不改变磁盘，也不删除 AI 分析记录。

### 5.1 路径可读性

- From/To 路径使用中间省略，优先保留盘符、末级目录和文件名，避免长路径隐藏真正的操作对象。
- 完整路径通过悬停提示和“复制”按钮提供；复制内容只用于查看，实际执行仍只使用 Rust 生成并复核的计划路径。
- 路径区域允许换行/收缩而不挤压确认按钮；Windows 扩展前缀仅保留在内部数据，界面显示普通盘符或 UNC 路径。

### 5.3 确认并执行

1. 用户点击“确认并执行”。
2. 前端只提交 `planId`，不能重新提交源路径或目标路径。
3. Rust 在每项执行前复核文件身份、授权边界和目标冲突。
4. 已确认的 `AiOrganize` 操作可在授权根目录内创建或复用由有效分类 ID 派生的一层目录。
5. 执行结果写入历史；界面按真实结果显示全部成功、部分失败或失败。
6. `planId` 一经消费不可再次执行。

按钮固定在预览卡片右下方：“取消计划”在左，“确认并执行”在右。

## 6. 历史与撤销

1. 页面按时间倒序读取真实执行记录。
2. 可撤销记录显示“撤销”，不可撤销记录显示“不可撤销”。
3. 用户点击“撤销”后先展示撤销预览或明确影响范围。
4. Rust 在撤销前再次检查文件身份、目标占用和授权边界。
5. 撤销成功后刷新记录状态；失败时保留原记录并展示原因。

撤销不能被描述为绝对保证。只有当前磁盘状态仍符合安全条件时才允许执行。

## 7. 模板管理

### 7.1 模板库状态

- 系统允许零个或一个全局模板；一旦存在全局模板，同一时刻只能有一个。
- 全局模板显示“当前全局”，可查看/修改和重命名分类内容，不提供删除动作。
- “常用模板”列表包含全部模板，包括当前全局模板；每个条目都可查看/修改，模板名称和分类内容按模板 ID 同步到另一分组。
- 非全局模板在常用列表中还可重命名、设为全局和删除；保存后可在后续分析中复用。
- 当前选中的模板在左侧高亮，右侧编辑器显示其真实内容和版本。
- 同一个模板在全局分组和常用模板列表中使用相同的模板 ID；从任一位置切换或修改都会同步另一处显示。
- 模板工作区在桌面端保持稳定高度，超出模板或分类内容在对应面板内滚动；窄屏端恢复自然纵向布局。

### 7.2 新建模板

1. 用户点击“新建模板”。
2. 右侧进入未保存状态，要求填写唯一的非空名称并至少保留一个分类。
3. 分类 ID 必须稳定、唯一且符合 Rust 安全校验；名称和描述供用户与模型理解，不保存本地路径。
4. 保存成功后模板加入列表，默认仍是非全局模板。
5. 若这是第一个模板，界面提示用户可将它设为全局，但不隐式替用户做决定。

### 7.3 修改模板分类

1. 用户可新增、修改、启用/禁用和删除模板分类。
2. 保存时 Rust 校验分类数量、ID、名称、重复项和目标目录映射安全性。
3. 分类定义发生变化时模板版本递增。
4. 保存不会修改既有分析结果、当前目录分类副本或磁盘目录。
5. 已开始的分析继续使用启动时冻结的版本；之后的新分析使用新版本。

### 7.4 重命名

- 全局模板和常用模板都提供“重命名”。
- 重命名在右侧编辑器内完成，确认或取消都不离开当前页面；只改变显示名称和更新时间，不改变分类语义，因此不递增模板版本。
- 名称不能为空，且应在大小写不敏感比较下保持唯一。
- 后端必须执行名称非空和大小写不敏感的唯一性校验；不能只依赖前端校验。
- 保存、重命名、设为全局和删除完成后，前端应重新读取完整模板列表；并发响应不得用旧列表覆盖较新的模板状态。

### 7.5 设为全局

1. 用户在非全局模板上点击“设为全局”。
2. 确认框显示模板名称，并说明它将成为文件浏览页的默认选择。
3. Rust 在一个事务中替换全局引用；旧全局模板自动变为普通模板。
4. 设为全局不改分类内容、不递增模板版本、不自动应用到任何目录。
5. 完成后刷新模板列表和文件浏览页的默认选择。

### 7.6 删除模板

- 仅非全局模板可删除。
- 确认框明确：删除模板不会删除文件、目录、历史分析结果或已保存的当前目录分类。
- 正被未启动表单选中的模板可删除，但前端随后必须清空该选择。
- 后端保留分析结果中的模板 ID 与版本快照；不得通过级联删除历史结果。
- 若模板被不可安全解除的现有引用约束，删除应失败并说明如何处理，而不是绕过约束。

### 7.7 当前目录自定义分类

“当前目录自定义分类”继续保留为独立来源。编辑时沿用现有根目录分类的保存与安全删除规则；它不是模板，也不能设为全局。删除分类配置不删除对应物理目录或文件。

## 8. 模型状态与错误处理

- 顶栏和设置页显示同一份真实 Provider 健康状态；状态包含 Provider 类型和模型，但不包含 API Key。
- 模型不可用时，文件浏览与模板编辑仍可使用，但“分析所选文件”禁用并给出恢复提示。
- 原型中的模型名称仅为示例；运行时不得硬编码为某个展示值。API 配置成功后显示实际模型和地址摘要。
- 网络或 Provider 错误不得触发自动文件操作。
- 远程内容发送被拒绝时，保留文件选择和分类方案，不产生远程分析请求。
- 表单错误贴近字段显示；系统错误显示在操作区并允许重试。

## 9. 状态恢复

- 页面刷新后恢复授权根目录、已保存模板和持久化历史。
- 未保存模板编辑、临时文件勾选和内存 `planId` 不保证跨应用重启恢复。
- 应用重启后旧 `planId` 必须无效。
- 若后台分析仍由当前进程管理，页面重进时通过批次状态恢复进度；应用退出后按现有任务生命周期处理，不伪造完成状态。

## 10. 验收场景

至少覆盖以下端到端场景：

1. 选择文件 → 选择全局模板 → 分析 → 接受 → 预览 → 确认执行 → 历史可见。
2. 选择非全局模板分析，不改变全局设置和当前目录分类配置。
3. 使用当前目录自定义分类分析。
4. 新建模板、修改分类、重命名、设为全局并在文件页成为默认值。
5. 全局模板可重命名但不可删除；常用模板可重命名、设为全局和删除。
6. 全局模板同时出现在全局分组和常用模板列表，两个入口编辑同一份模板。
7. 删除非全局模板不删除文件、目录和历史结果。
8. 模板在分析前被修改或删除时拒绝陈旧提交。
9. 模板在分析开始后被修改，当前批次仍记录并使用冻结版本。
10. 取消预览不修改磁盘；重复确认同一 `planId` 被拒绝。
11. 200% 缩放和窄窗口下，按钮、表单和关键信息仍可访问。
12. 配置本地 Ollama 与 OpenAI 兼容 API；分别测试健康状态，远程分析在确认与拒绝两条路径下都符合提示和请求约束。
