# ai-file-sorter UI 设计规范

## 1. 文档目的

本文定义 `ai-file-sorter` 前端的视觉语言、页面结构和组件规则。React 已按当前完整版 HTML 原型完成主要视图迁移；Rust 安全模型和真实 API 仍是交互行为的规范来源。

设计基线：[`ai-file-sorter.html`](./ai-file-sorter.html)

## 2. 产品体验目标

界面首先服务于三件事：快速判断当前目录状态、清楚理解 AI 建议、在文件变化前完成安全确认。

- **安静**：采用低饱和米白与鼠尾草绿，避免大面积深色和高对比色抢夺注意力。
- **可信**：原文件、建议结果、操作预览和最终执行保持清晰分层。
- **克制**：只显示用户完成当前任务所需的信息，不显示设计说明、实现说明或内部流程文案。
- **一致**：相同层级的卡片、按钮、标签和状态使用相同尺寸与对齐方式。
- **可读**：常用正文不低于 `13px`，辅助信息不低于 `11px`。

## 3. 品牌与字体

### 3.1 名称与图标

- 产品名统一为 `ai-file-sorter`。
- 图标采用原创圆角方形图标：绿色渐变底、文件夹轮廓与 AI 星芒。
- 风格参考 Apple 平台图标的圆角、层次和柔和高光，但不得复制 Apple 商标或系统图标。

### 3.2 字体栈

```css
font-family: "JetBrains Mono", "Microsoft YaHei", monospace;
```

- 英文、数字和路径优先使用 JetBrains Mono 2.304。
- JetBrains Mono 不包含完整中文字形，中文由 `Microsoft YaHei` 回退显示。
- 若产品发布包需要稳定呈现，必须随应用打包字体文件并通过 `@font-face` 引用；只写字体名不能保证用户设备已安装对应版本。

### 3.3 字号层级

| 用途 | 字号 | 建议字重 |
| --- | ---: | ---: |
| 页面主标题 | 30px | 600 |
| 区块标题 / 品牌名 | 18px | 600 |
| 导航 | 14px | 700（选中项） |
| 正文、表格、表单、主要按钮 | 13px | 400–800 |
| 辅助说明、徽标、次级按钮 | 12px | 400–750 |
| 表头、极短元信息 | 11px | 400–750 |

正文不得再次缩小到难以阅读的尺寸。长路径使用省略号，并通过悬停或详情视图提供完整内容。
Windows `\\?\\` 扩展路径前缀仅保留在内部安全与文件操作数据中；用户界面显示为普通盘符或 UNC 路径。

## 4. 色彩系统

| 语义 | 色值 | 使用位置 |
| --- | --- | --- |
| 应用画布 | `#f8f6f0` | 主背景 |
| 侧栏 | `#ebe7dd` | 左侧导航 |
| 表面 | `#fffdf8` | 卡片、输入框、表格 |
| 分隔线 | `#ddd7cb` | 边框与分隔线 |
| 主文本 | `#242824` | 标题、正文 |
| 次文本 | `#8d8c84` | 元信息、提示 |
| 主操作绿 | `#78937f` | 一般主按钮、成功状态 |
| 深品牌绿 | `#365744` | 图标、强调文本 |
| 选中背景 | `#e4ebe1` | 已选择区域、当前项 |
| 执行确认 | `#d6ae63` | “确认并执行” |
| 危险文本 | `#9a6b64` | 删除、拒绝等危险动作 |

大面积区域使用浅色。深绿只用于品牌小面积和必要强调；琥珀色只用于会真正改变文件的最终确认操作。

## 5. 全局布局

- 桌面端采用 `260px` 固定侧栏与自适应主内容区。
- 顶栏高度 `72px`，显示当前授权目录和本地 AI 状态。
- 页面内容默认水平内边距约 `27px`，纵向内边距约 `25px`。
- 主要卡片圆角 `13–15px`，按钮圆角 `8–9px`，状态徽标使用胶囊形。
- 页面必须占满应用窗口，不展示原型说明横幅或设计方案标识。

响应式规则：

- 小于 `950px`：侧栏收窄为图标栏，双栏内容改为单栏。
- 小于 `650px`：隐藏侧栏，工具栏、选择栏和操作区纵向排列。
- 桌面应用仍以宽度不小于 `950px` 为主要验收尺寸；窄屏不得出现内容重叠或横向裁切。

## 6. 导航与页面结构

侧栏保持五个一级入口：

1. 文件浏览
2. AI 建议审查
3. 操作预览
4. 历史与撤销
5. 模型与分类设置

“当前目录”条目用于显示正在管理的授权根目录，并帮助用户确认操作范围。它不是新的文件选择入口；更换授权目录仍由文件浏览页的“选择其他目录”完成。

### 6.1 文件浏览

页面由目录状态、搜索与筛选、文件表格、选择操作栏组成。

- 只有选择文件后才显示或启用批量操作。
- 分类方案选择放在选择操作栏中；存在全局模板时默认选中它，否则要求用户显式选择。
- 用户也可选择其他已保存模板或“当前目录自定义分类”。
- “管理分类”进入设置页对应的模板或当前目录分类编辑状态。
- 模板选择只决定本次 AI 分析使用的分类集合，不应立即修改目录配置或创建文件夹。

### 6.2 AI 建议审查

- 每个文件使用相同结构的独立卡片。
- 卡片固定呈现“原文件 → AI 建议”、置信度、简短原因和“接受建议 / 修改 / 拒绝”。
- 多条建议必须保持左右结构、字段顺序和操作位置一致。
- 置信度胶囊使用 `inline-flex` 居中，固定最小宽度和高度，避免文字视觉偏移。
- 右侧分析设置仅包含用户当前可修改的真实设置，不显示实现说明。

### 6.3 操作预览

- 使用整宽 From → To 卡片逐项展示源路径和目标路径。
- “取消计划”与“确认并执行”并排放在卡片右下方，与内容分隔后对齐。
- “确认并执行”使用琥珀色；“取消计划”使用中性描边样式。
- 不再设置独立、突兀的右侧按钮卡片。

### 6.4 历史与撤销

- 每条记录保持“时间 / 操作摘要 / 状态或动作”的统一三列结构。
- 可撤销记录显示浅绿色“撤销”按钮；不可撤销记录显示相同尺寸的禁用状态块。
- 禁止只靠颜色表达可撤销性，必须同时显示文字。

### 6.5 模型与分类设置

页面分为模型状态条和模板管理工作区。

- 左侧为模板库，按“全局模板（默认）”与“常用模板”分组；所有模板可新建、查看/修改和重命名，常用模板还可设为全局或删除。
- 右侧为当前模板编辑器，编辑分类名称、描述和启用状态。
- 全局模板可查看、修改和重命名分类内容，但不能删除。
- 常用模板可重命名、设为全局和删除，并在后续分析中继续复用。
- 页面中不提供“应用模板”按钮；模板由用户在文件浏览页开始分析前选择。
- “当前目录自定义分类”作为另一种分类来源保留，其管理入口由文件浏览页跳转到本页对应编辑状态。

## 7. 组件规则

### 7.1 按钮

- 每个页面最多一个视觉最强的主动作。
- 真正修改磁盘的动作必须与普通保存动作有视觉区别。
- 删除使用危险文本色和二次确认，不使用高饱和红色铺满按钮。
- 按钮文本水平与垂直居中，常规高度不少于 `38px`，最终确认按钮高度不少于 `42px`。

### 7.2 表单与列表

- 输入框、下拉框和按钮共享相近高度、圆角和边框颜色。
- 空状态直接说明用户下一步可做什么，但不展示开发者说明。
- 模板名、分类名和路径过长时不挤压操作区；使用省略与完整值查看机制。

### 7.3 反馈状态

所有异步动作至少具有：默认、处理中、成功、失败四种状态。处理中禁用重复提交；失败消息说明用户可以如何恢复。成功反馈不得让用户误以为文件已经移动，除非安全执行链确实完成。

## 8. 无障碍与最终验收

- 正文与背景需保持可读对比度；浅绿色背景上的文字不得继续变浅。
- 键盘可访问所有按钮、列表项和表单控件，并显示清晰焦点环。
- 图标按钮必须提供可访问名称，状态不能只依赖图标或颜色。
- 200% 缩放下，主要流程仍可完成。
- 页面不得出现设计方案名称、开发说明、内部安全实现说明或用户要求删除的辅助文案。
- 最终实现应逐页与 HTML 基线对照，但数据、状态和错误信息必须来自真实程序，而非写死的演示内容。
